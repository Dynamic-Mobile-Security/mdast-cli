# STG-5242: восстановление скачивания App Store при пустом ответе Apple

## Проблема

CLI 2026.9.1 успешно получает сессию, но volumeStoreDownloadProduct отвечает HTTP 200, status=0, authorized=false и songList=[]. Повтор исходного запроса не восстанавливает скачивание. Актуальный ipatool использует redownload/update из Apple bag; main от 18.09.2026 добавляет consumer-каталоги, когда enterprise-каталог не содержит приложения.

## Поведение и границы

Обычный успешный ответ и существующие ошибки лицензии/сессии сохраняются. Для пустого успешного ответа без failureType/customerMessage/cancel используется ограниченный fallback: проверенные endpoints из bag, поиск точной iOS-версии в регионе аккаунта (enterprisestore, iphone, ipad), redownload, при пустом HTTP 500 или No Longer Available от redownload один updateProduct. Перед использованием результата проверяются app ID, версия и bundle ID. Запросы имеют таймауты, запрещают redirects и автоматические POST-повторы; пароли и полные ответы не выводятся. Не менять SAP-вход, настройки магазинов, обход лицензий, поддержку иных платформ и стенды.

## Приёмка

1. Регрессионные тесты обычного скачивания и auth/license ошибок остаются успешными.
2. Покрыты consumer-каталог, redownload и update, недоступная версия, неверный endpoint, неожиданный ответ, несовпадение app/version/bundle; повторы ограничены.
3. Подтверждены реальные валидные IPA двух контрольных приложений с теми же учётными данными и идентификатором устройства, с которыми исходный CLI отказал.
4. До живого подтверждения считать изменение кандидатом. Код в рабочем окружении не заменять автоматически.

## Проверка 21.09.2026

Кандидат проверен настоящим entrypoint CLI с пустыми временными каталогами: два контрольных приложения на двух аккаунтах, четыре успешные загрузки. Для каждой IPA проверены ZIP CRC, структура и платформа iPhoneOS. На одном аккаунте сработали consumer-каталог и переход с пустого HTTP 500 redownload на update; на другом enterprise-каталог и переход с No Longer Available на update. Во всех четырёх случаях update вернул файл с authorized=false, поэтому этот флаг отдельно не считается отказом. Регрессионные тесты auth, SAP и восстановления скачивания: 104 passed.

Это проверка локального кандидата CLI. Установленные dev/prod, зависимости монолита и настройки аккаунтов не изменены. Полный путь UI/REST/Celery и повторное скачивание из сохранённой сессии в эту проверку не входили.
