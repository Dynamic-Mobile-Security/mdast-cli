# STG-5405: подтверждение запуска после потерянного ответа

Задача: https://tracker.yandex.ru/STG-5405

## Проблема

Scanyon продолжает запуск после таймаута Clark. Повтор Clark возвращает 409,
а CLI может получить ReadTimeout раньше ответа. Существующая обработка 409
также принимает отсутствующую или отменённую стадию за успешный запуск.

## Решение и границы

- Отправлять POST запуска один раз. После Timeout/ConnectionError, HTTP 409
  или 502/503/504 проверять только GET существующего scan_id.
- Не более 6 запросов проверки с обычным интервалом опроса, без вложенных
  циклов retry. Каждый HTTP-запрос сохраняет существующий timeout.
- Подтверждение: ответ с тем же ID, известной стадией START/WORKING/STOP/SUCCESS,
  непустым строковым status, отличным от FAIL. Промежуточные статусы расширяются
  сервером, поэтому их полный перечень не фиксируется в клиенте.
- FAIL/CANCELLED дают SCAN_FAILED, 401/403 сохраняют AUTH_ERROR. Created
  проверяется повторно; неизвестные/неполные ответы не подтверждают запуск.
- Неопределённый результат содержит scan_id и указание проверить существующий
  скан перед повторным запуском CLI. При 409 + Created сохраняется SCAN_FAILED.
- Штатный HTTP 200, ожидание скана, --nowait и монолит сохраняют поведение.

Scanyon.start уже проверяет Created и fsm_locked под Redis-блокировкой FSM.
Его синхронный запуск и Clark в этой правке не меняются. Перенос в фоновую задачу
без гарантированного восстановления не входит в исправление CLI.

## Приёмка

Проверить потерянный ответ после принятия запуска, Created с последующим START,
исчерпание попыток, сетевые ошибки GET, HTTP 409/502/503/504, ошибки доступа,
FAIL/CANCELLED, пустой/неверный JSON и несовпадающий ID. Во всех сценариях
выполняется не более одного POST start и не создаётся дополнительный скан.
Проверить полный CLI flow с --nowait и обычным ожиданием, затем весь pytest.

## Результат проверки

Полный pytest: 443 passed, 1 skipped. Проверены оба CLI-сценария после
ReadTimeout: --nowait и ожидание результата, по одному созданию и запуску.
