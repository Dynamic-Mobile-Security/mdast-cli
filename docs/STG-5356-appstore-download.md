# STG-5356: App Store через обычный интерфейс CLI

## Исправленные дефекты

CLI передавала `None` вместо пароля при пустом `--appstore_2FA`. Отсутствующий код отклонялся ещё при разборе аргументов, даже когда есть сохранённая сессия. Теперь отдельный пароль передаётся без потери, код добавляется при наличии, пробелы в коде убираются. Старый `--appstore_password2FA` совместим. Если Apple возвращает `MZFinance.BadLogin.Configurator_message`, CLI предлагает свежий код и завершает вход.

Временные ответы без account plist повторяются максимум три раза на том же проверенном auth URL. Паузы 10/20 секунд, `Retry-After` имеет приоритет; ожидание больше 30 секунд завершает запрос без преждевременного повтора. HTTP 204/404/429/5xx, HTML 403 и наблюдаемый HTML 301 без Location учитываются отдельно от ошибок аккаунта. Подпись заново вычисляется для неизменённого тела и protocol attempt. Сертификатные ошибки не повторяются.

Относительный Location сначала разрешается относительно проверенного URL, затем проходит прежний allowlist. Некорректный присутствующий Location не повторяется, credentials на него не отправляются. Для HTML 301 без Location разрешён только повтор исходного адреса, без догадки о новом endpoint и без unsigned fallback.

Классификация временных отказов и backoff сверены с текущим [upstream](https://github.com/majd/ipatool/blob/main/pkg/appstore/appstore_login.go). Подобный HTML 301 описан в [issue 519](https://github.com/majd/ipatool/issues/519); upstream v2.5.0 использует короткие паузы 0,25/0,5 секунды и не содержит всех правок текущего main.

## Проверки 05.10.2026

- Полный набор после локальной настройки signer: 361 тест успешен. Отдельный security gate: 20 тестов успешны.
- Добавлены проверки передачи credentials через обычные аргументы, bounded retries, backoff, Retry-After (число/дата/слишком долго), точной подписи, остановки на ошибках аккаунта/TLS, безопасного относительного redirect и отсутствия утечек.
- Изолированный процесс существующего dev-контейнера выполняет `mdast_scan.main()` с кандидатными модулями в памяти. Установленная CLI, БД, конфигурация и общие сессии не меняются.
- Последний штатный путь кандидата: основной Apple host вернул 302 на Store pod, затем pod вернул 204/404/204. CLI завершилась DOWNLOAD_FAILED, IPA нет. Повтор из сохранённой сессии не выполнен, потому что вход не завершился.
- Диагностическая идентичность устройства через MAC вместо GUID аккаунта получила HTML 301 без Location. Менять GUID в продуктовой реализации оснований нет.
- Независимый контроль Go net/http с тем же опубликованным Linux signer также получил 204/403, пригодного account plist нет. Замена requests на Go не доказана как исправление.

## Статус приёмки

Исправлены воспроизводимые дефекты CLI, но успешный свежий вход и IPA пока не получены. Это кандидат для review, а не готовый релиз. Не создавать релизный тег, не публиковать пакет и не доставлять его на стенды до выполнения end-to-end критериев спецификации.

Внутренняя причина отказа Apple не установлена. HTTP-статусы сами по себе не доказывают неверные credentials. Ранее присланный OTP повторно проверен только по явному разрешению пользователя, результат приведён ниже. Локальный native ARM64 signer отдельно ограничен sandbox/sysctl; это не тот же отказ, что Linux HTTP-ответы.

## Локальный macOS signer

Native ARM64 Unicorn в ограниченной среде падает при инициализации. Явный `MDAST_APPSTORE_SAP_ARCH=amd64` выбирает поставляемый Intel helper через существующую Rosetta. `MDAST_SAP_CACHE_DIR` задаёт абсолютный доступный каталог для проверенных public runtime assets, без изменения HOME. Account cache остаётся отдельным. Нет автоматического fallback, другой signer, изменения runtime dylib, TLS или sandbox.

Штатный signer из установленного кандидатного wheel успешно открыл SAP-сессию и вернул подпись 501 байт за 4,59 секунды. Собраны все шесть helpers; optional cache hook проверен Go-тестами и включён в воспроизводимую сборку и sdist. Google Play DaOffice (44 901 269 байт, 4 APK) и Wikipedia (27 127 132 байта, 3 APK) успешно скачаны обычным CLI entrypoint, фактическая ABI x86_64, архивы проверены. Runtime crypto-зависимости не менялись.

Это подтверждает исправленный локальный запуск signer, а не полную приёмку Apple: fresh login/IPA с новым 2FA ещё не проверены. Предоставленный ранее OTP устарел; запрошен свежий код для следующего контрольного входа. Неверный пароль не установлен.


## Контроль со старым кодом по разрешению пользователя, 05.10.2026

Свежего 2FA у пользователя нет; он явно разрешил проверить ранее присланный код. Обычный entrypoint установленного local candidate с packaged darwin-amd64 signer через Rosetta и отдельным доступным cache дошёл до auth POST:301 без Location, затем204 и404. Через34,67с CLI завершилась exit4; account plist и IPA не получены. Это уже проверка штатного локального signer, без удалённого signer и подмены исходников. Код передан в памяти через stdin и не сохранён. Поскольку Apple не вернул account plist, неверный пароль или код не установлены. Fresh login здесь означает новую сессию, а не свежесть OTP. Проверка других IPA и второго процесса остановлена: новая сессия не создана.

Сверка состава auth payload с текущим upstream ipatool: те же appleId, attempt, guid, password+code, rmp и why; createSession не отправляется в обеих реализациях. Подтверждённого расхождения payload, которое объясняет этот отказ, нет. Повторять неизменённый вход без нового диагностического условия не планируется. Полная приёмка App Store не пройдена; draft PR157 не смёржен, новая версия не опубликована и не доставлена.
