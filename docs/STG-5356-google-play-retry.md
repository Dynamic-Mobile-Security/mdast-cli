# STG-5356: Google Play и приёмка магазинов

## Проблема

Временный HTTP 503 повторяется немедленно, затем превращается в обычный RuntimeError. Markea не запускает свой отложенный retry. Отказы авторизации выбранных интеграций требуют отдельной диагностики.

## Решение и границы

- Выделить тип временной ошибки Google Play для HTTP 408/429/5xx и распознаваемых сетевых сбоев. Не повторять постоянные HTTP 4xx, auth-ошибки, неизвестные ошибки и невалидные APK.
- CLI повторяет временные ошибки с ограниченными задержками в общем deadline загрузки. Отмена процесса сохраняет cleanup дочернего процесса.
- Markea использует свой существующий бюджет и задержки, без вложенного умножения повторов. Обёртка сохраняет временную природу ошибки.
- ARM fallback остаётся только для явно недоступной x86-сборки.
- Не ослаблять TLS, не логировать credentials, не менять proxy или аккаунты без установленной причины.
- Проверить Google Play, App Store и RuStore в standalone CLI, монолитном dev и Kubernetes dev: скачивание и валидность APK/IPA. Prod и отдельный SaaS только диагностика, без доставки и изменений.

## Критерии

503 -> успех; исчерпание бюджета; соблюдение deadline; 401/403 fail-fast; отсутствие лишнего ARM fallback; очистка артефактов между попытками; свежие положительные download-only проверки всех трёх магазинов на dev. Недоступные credentials/внешний provider отмечаются как блокеры, не как успешно исправленные.
