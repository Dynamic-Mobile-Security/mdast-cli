# Приоритет iOS при автоматическом выборе архитектуры

## Требование

По решению пользователя от 08.10.2026 порядок выбора: iOS 16, затем iOS 15,
затем iOS 14. Сейчас CLI предпочитает iOS 14 независимо от порядка каталога.

## Границы

- Общий дефолт iOS становится 16.
- Kubernetes и монолит выбирают первую присутствующую архитектуру из порядка 16/15/14.
- Порядок записей каталога не влияет на этот приоритет.
- Явный architecture_id в монолите сохраняет приоритет над автоматическим выбором.
- Android, обработка движков и контракт API не меняются.
- Если ни одной из трёх архитектур нет, сохраняется прежнее поведение:
  Kubernetes берёт первую подходящую iOS-запись, монолит просит явный architecture_id.
- Изменение не добавляет выбор ОС по доступности устройств организации.

## Приёмка

Тесты покрывают разные порядки каталога, fallback 16 → 15 → 14,
пустой/неподходящий каталог, прежний Android-дефолт и явный выбор в монолите.
По подтверждению пользователя публикуется релиз 2026.10.4 в GitHub, PyPI и Docker.
Версии setup.py и mdast_cli/__init__.py синхронизируются.
Перед публикацией должен пройти полный CI; после публикации проверяется версия пакета и образа.

## Результаты проверки 08.10.2026

- 128 тестов прошли, git diff --check без ошибок.
- Изменённая локальная CLI выбрала iOS 16 на dev, скан 20399.
- Скан дошёл до SUCCESS/PARTIAL_COMPLETE, exit code 0, JSON и PDF получены.
- Неполнота вызвана отсутствием зарегистрированного сервиса app_dump.
  Также зафиксированы падения контрольного приложения. Эти проблемы
  не исправляются изменением порядка выбора ОС.
- Полный локальный набор: 410 passed, 1 skipped. Публикация 2026.10.4 выполняется после CI.
