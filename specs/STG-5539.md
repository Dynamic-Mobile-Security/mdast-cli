# STG-5539: Go в Docker-сборке CLI

## Подтверждённая проблема

Два согласованных pin GitHub Actions обновлены до Go 1.27.3. PyPI wheel собирается через этот toolchain. Но Dockerfile имеет отдельный FROM golang:1.27.1-bookworm, пропущенный при подготовке предыдущего плана. Опубликованный Docker helper извлечён из образа mobilesecurity/mdast_cli:2026.11.2: build info подтверждает go1.27.1 и compress 1.18.7. Ответственность за неполную проверку плана на агенте.

## Конкретное исправление

Одна строка Dockerfile: FROM golang:1.27.1-bookworm AS go-toolchain заменить на FROM golang:1.27.3-bookworm AS go-toolchain. Остальной код, workflow и зависимости не менять. Добавить проверку согласованности pin в существующие packaging/build tests, чтобы этот пропуск не повторился.

Тег 2026.11.2 уже опубликован и указывает на merge commit. Его не переписывать. Если согласовано исправить также Docker, выпустить следующий patch 2026.11.3 через новый PR/MR, затем направить потребителей сразу на проверенный wheel 2026.11.3. На момент реализации уже открыты MR монолита !1183 и Markea !91 на 2026.11.2; они ещё не смержены. Обновить их новыми коммитами на опубликованную 2026.11.3, сохранив ветки и историю MR.

## Приёмка

- PR CI успешен на точном SHA перед merge.
- Все пути сборки используют Go 1.27.3.
- После публикации извлечь Linux helper из Docker-образа и wheel; build info и checksum подтверждают нужный toolchain и compress.
- Trivy обоих Linux helpers: 0 HIGH/CRITICAL; готовый образ Markea проходит штатный Trivy Image.
- Штатные тесты и изолированная IPA-проверка для изменённого helper сохранены.
- Не обходить CI, не перезаписывать выпущенные версии, не менять инфраструктуру и не запускать ручной deploy.

## Согласование 06.11.2026

Пользователь разрешил весь план: исправить Docker, выпустить 2026.11.3 через новый PR и направить существующие MRs потребителей на него. README локальной сборки также должен указывать исправленный Go. Инфраструктура и ручной deploy вне scope. Задача: https://tracker.yandex.ru/STG-5539.

## Локальная проверка

488 pytest passed с native helper. Все шесть helpers заново собраны Go 1.27.3 и побайтно совпали с проверенной PyPI-сборкой 2026.11.2. Python-клиент не менялся; реальная Linux IPA-проверка этих exact bytes выполнена в STG-5538. Новый тест предотвращает расхождение Docker, PyPI/test workflows и README.

Локальный Docker sap-builder (Linux arm64) собран из исправленного Dockerfile. Извлечённый helper совпал с кандидатом по SHA256, build info подтверждает Go 1.27.3/compress 1.18.7. Trivy распознал Go-бинарник, 0 HIGH/CRITICAL. Временный контейнер и именованный локальный образ удалены. Опубликованный Docker Linux amd64 проверяется отдельно после штатного workflow.
